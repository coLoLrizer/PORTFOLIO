# Timur's Portfolio

Every system I build, I try to exploit first.

I design boss fights and ability systems by playing against my own assumptions — checking dodge windows against real player stats, finding the exploit before a player would, and not calling a mechanic done until I've genuinely failed to break it.

## Included

**[NO HIT!](NO_HIT!%20case%20study.md)** — solo boss fight, shipped to CrazyGames in 4 days, first time in Construct 3. Fully deterministic — every attack dodge-checked against real player stats (speed, cooldown) so nothing is beatable for free. Phase 2 keeps the same five attacks but reworks the correct dodge for each — same identity, different solution.
[▶ Play it](https://www.crazygames.com/preview/257a3540-822d-4ce8-ab83-57f2d0f22fde)

**[Crimson Witch](CrimsonWitch.md)** — a simple resource idea (a limited potion pool the boss has to keep re-brewing mid-fight) that grew into a boss whose death reshapes the game's economy. Reviewed by a **Senior Game Designer at Blizzard**: *"a strong theme."*
[▶ Watch breakdown](https://youtu.be/bGkVlFrUSY4)

**[Monolith](Monolith.md)** — orbital ability system solved through quadrant math and dual-tangent orbit logic. Always picks the biggest arc, stays stable under camera rotation, never flies into the player's face.

**[Telekinetic](Telekinetic.md)** — Wynncraft-style class, 3 archetypes (physics-based tank, chaos burst, elemental flow), DPS-verified across 25+ builds.

**[Blightfall: Crimson Veil](Blightfall.md)** — systems design and team coordination on a shipped 7-person Hytale mod. Honest postmortem: what shipped, what didn't, and why.

**[Orbital Strike](Orbital_Strike_Evolution.md)** — case study on how one ability idea evolved across three design contexts (fantasy → prototype → MMO-ready).
